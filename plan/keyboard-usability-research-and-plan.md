# FreeShiamy 鍵盤好按度研究與功能計畫

日期：2026-10-23。狀態：第一階段與追加需求已完成；驗證範圍見第 11、12 節。分支：`feat/keyboard-usability`。

目標是減少誤按、漏按、意外長按及修正文字的操作成本。以手機直向、嘸蝦米字碼輸入為主要情境，將使用者喜歡的 Gboard 當作操作習慣參考。本文的尺寸與時間是**待實測的設計起點**，不是 Gboard 規格或人體工學的通用最佳值。

## 1. 結論與範圍

採用唯一的 Gboard 式錯列配置，以使用者提供的英文鍵盤圖片為視覺參考。保留完整觸控區域，以無邊框淺色鍵帽、自然錯列與寬空白鍵改善整體排列。提供按鍵放大預覽並移除文字靠上；保留高度百分比、數字列、觸覺回饋、永遠顯示鍵盤，以及候選與隱私設定；刪除舊排版選單、QAZ 左移與尺寸預設。

第一階段做尺寸、鍵帽間隔、候選列與回饋；第二階段做全鍵可調長按及游標操作。數字列、Emoji 入口、字根提示與同音反查已存在，應改善而非重做。剪貼簿、文字編輯與數字專用版面是後續實用功能；滑行拼字、雲端翻譯及 AI 改寫暫不納入首版。

| 刪除鍵 | `FreeShiamyIME.kt:292,505`：從 raw buffer 開始的連刪，不越過邊界刪外部文字 | 必須保留這項保護，不能因調快連刪或加入手勢而穿透 |

尺寸換算例：假設可用寬 360dp，忽略實際像素取整，9% = 32.4dp；7.5% = 27dp，1.5% gap = 5.4dp。按鍵矩形寬少了約 16.7%。Framework 另有鄰近鍵判定，因此不能由矩形尺寸直接推論所有 gap 都不可按。

另外以 XML 的 key width + preceding gap 加總，spacious 兩版底列名目寬皆為 102.5%p。這是需要檢查的幾何條件，**尚不代表實際畫面裁切**；framework resize、容器寬度與像素取整可能改變結果。

## 3. 外部證據與適用邊界

### Gboard 可以借鏡的操作

Google 官方列出空白鍵移游標、從刪除鍵左滑刪除多字、常駐數字列、長按符號提示、單手模式和按鍵邊框；說明文件也列出雙擊 Shift、長按空白鍵切換語言。這些是可驗證的操作參考；本次查閱的官方資料未提供內部長按／連發時間或觸控區尺寸。[Gboard 官方商店說明](https://play.google.com/store/apps/details?id=com.google.android.inputmethod.latin&hl=en)、[Gboard 使用說明](https://support.google.com/gboard/answer/2842292?hl=en)。

剪貼簿支援貼上及釘選，未釘選歷史會在一段時間後清除；Google 未在此頁給出固定秒數。適合借鏡「臨時內容與使用者主動保存的片語分開」這個行為。[Gboard 剪貼簿說明](https://support.google.com/gboard/answer/10742542?hl=en)。

### 尺寸不能直接套用一個數字

Android 的一般無障礙建議是至少 48 × 48dp 的觸控目標，並允許可見圖形小於觸控範圍。這支持把鍵帽與可按範圍分開；但沒有由此建立「手機字母鍵一律 48dp 寬」的規則。十鍵一列即需 480dp，對 360dp 手機無法成立，也不能宣稱較小字母鍵已滿足這項一般建議。[Android 觸控目標指引](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views?hl=en)。

Parhi 等人的單手拇指研究有 20 名參與者，以小型 PDA 測單點和連續數字鍵操作，作者提出約 9.2／9.6mm 的尺寸建議。它不是現代手機 QWERTY 字碼輸入研究，不能拿該毫米值直接訂本專案每一鍵的寬度；閱讀其裝置、握法與操作任務限制後，本計畫不將該尺寸外推為手機字母鍵的最佳值。[原始研究：Target Size Study for One-Handed Thumb Use on Small Touchscreen Devices，MobileHCI 2006](https://www.microsoft.com/en-us/research/wp-content/uploads/2006/01/parhi-mobileHCI06.pdf)。

因此下列 dp 尺寸是配合手機寬度與目前程式提出的假設，仍需本人輸入測試；不把桌上觸控鍵盤、數字鍵盤的間距研究當作手機全鍵盤的最佳值。dp 也不應直接當成精確的實體毫米。

### 目前用到的 Android framework 行為

API 34 的 AOSP `KeyboardView` 中，一般鍵在放開時送出；repeatable 鍵在按下時先送一次，400ms 後以 50ms 間隔連發；長按採 `ViewConfiguration.getLongPressTimeout()`。70ms 的 debounce 用於抬起時選擇目前／前一顆鍵，**不是每次按鍵固定多等 70ms**。這些只是讀到的 framework 實作範例，不是 Gboard 數據，也不是所有 Android／廠商版本的保證。[AOSP API 34 KeyboardView](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/%2B/refs/heads/androidx-transition-release/android-34/android/inputmethodservice/KeyboardView.java)。

`KeyboardView` 已於 API 29 deprecated；官方建議既有使用者可複製 AOSP 實作或自行實作。不能以此推論必須立即重寫，但全鍵長按／連發設定也無法只靠修改鍵盤 XML 完成。[KeyboardView 官方 API 說明](https://developer.android.com/reference/android/inputmethodservice/KeyboardView)。

## 4. 建議尺寸與排版

### 共通尺寸：第一輪實測起點

| 項目 | 起點 | 調整原則 |
| --- | --- | --- |
| 字母列高 | 固定基準 52dp，套用既有高度百分比 | 只有一版排列；高度調整不拉伸字體 |
| 數字列／底列 | 48dp／56dp | 數字列保持可開關；高度不足時依可用高度壓縮，避免溢出 |
| 鍵帽水平間隔 | 4dp，即各鍵左右各內縮 2dp | 內縮只改繪製，整個 cell 仍能判定；不把 4dp 塞進實際 horizontalGap |
| 鍵帽垂直間隔 | 6dp，即上下各內縮 3dp | 垂直觸控 cell 連續，邊界只有一個決定規則 |
| 字體 | 主字 20–22sp、副符號 11–12sp | 與列高分離，並檢查系統大字體；不做單純垂直拉伸 |
| 候選列 | 高 48dp，單項觸控寬至少 48dp | 字數較多的候選自然加寬並橫向捲動，不為塞進十字縮小按鈕 |
| raw code 區 | 約 56–72dp，長碼可展開查看 | 減少固定 35% 權重對候選的擠壓；保留點擊送出原碼功能 |
| 底部位置 | 扣除系統 inset 後布局；可選上移 | inset 只計一次；導航手勢與橫向模式須實測 |

以數字列 48dp、三列字母各 52dp、底列 56dp、候選列 48dp 計，總高約 308dp，未含系統 inset；目前名目總高約 287.5dp。多出的 20.5dp 是否值得，用可見編輯區與輸入成績一起評估。橫向依可用高度縮放，不讓按鍵超出輸入視窗。

```text
相鄰觸控 cell：|<------ A ------>|<------ S ------>|
可見鍵帽：       [     A     ]    [     S     ]
                  鍵帽間有空隙；觸控 cell 連續
```

### 唯一的熟悉型配置

依使用者確認，僅保留 `familiar` 一版排列，數字列為可開關的延伸功能。以下比例是本專案提案，不是量測 Gboard：

| 列 | 配置與寬度 | 加總 |
| --- | --- | --- |
| 數字 | 1–0，各 10% 可用寬 | 100% |
| Q | Q–P，各 10% | 100% |
| A | 左右各留 5%，A–L 各 10% | 100% |
| Z | Shift 15%，Z–M 各 10%，Del 15% | 100% |
| 底列 | 123 15%，`,` 10%，空白 50%，`.` 10%，Enter 15% | 100% |

這個版型把 Del 放到第三字母列，逗號與句點移到底列；依使用者追加確認，單引號收進 z 長按選單，反查入口保留，騰出的寬度交給空白鍵。地球與收鍵盤移到工具面板，面板在候選列保留一顆 48dp 入口，任何輸入狀態都可開啟；開工具時暫時替換候選內容，不自動送出 raw code。這會減少候選可見數，候選維持橫向捲動與展開操作。

在 360dp 可用寬，字母 cell 可達 36dp；Del／Enter 約 54dp。A 列左右留白屬於錯列布局，命中判定可延伸至外緣；不可讓已縮小的鍵帽或空隙造成漏按。不提供舊版型切換；舊排版偏好不再參與選擇。

## 5. 觸發時間與手勢規格

下表是第二階段的**可驗證提案**；第一階段保留原生全鍵 timer，先增加即時回饋及修正取消事件。

| 行為 | 建議起點 | 必要規則 |
| --- | --- | --- |
| 一般字母／數字 | 按下即顯示 pressed 與觸覺回饋；放開送出一次 | 不為等待長按增加固定輸入延遲；獨立連點同一鍵不能被當雜訊吞掉 |
| 長按符號／入口 | 預設跟隨系統；明確選擇自訂後可試 300／350／400／500ms，先比較 350 與 400ms | 系統設為較慢或啟用觸控探索時，預設沿用系統，不因升級覆寫；彈出後放開不能再送主鍵 |
| 刪除連發 | 按下刪一次，400ms 後開始，每 60ms 一次 | 與現行 50ms 比較控制感；首版不加速；保留 raw buffer 刪除邊界 |
| 空白長按 | 熟悉型版面先停用自動連發 | 已有按住選字／空白行為可能有使用者依賴，第一階段先保留既有空白連發，後續再評估停用；勿同時分配切換語言和連發 |
| Caps Lock | 雙擊 Shift 試用 350ms，對照現有 800ms | 只限連續兩次 Shift，中間輸入字母即清除雙擊資格；用單調時鐘 |
| 空白鍵移游標 | raw code 空時，水平位移 12dp 後進入；之後約每 12dp 移一格 | 初始值需調；進入後吃掉此次 tap，不再補空白；可逆向移動 |
| raw code 內右滑 | 維持目前 48dp 門檻與加空白語意 | 不偷偷送出字碼，也不改成外部游標移動 |
| 取消／隱藏／失去輸入連線 | 立即停止 timer，清除本次觸控狀態 | 不因取消新增空白／選字／刪除，不留下延遲 callback |

移游標先只支援已送出文字；raw code 存在時不移動外部游標，避免目前 `onUpdateSelection()` 清除暫存字碼。移動或刪除要考慮 emoji／組合字，不能直接把一個 UTF-16 code unit 當成一字。滑動刪除可後續加入，先提供選取預覽；若做復原，只承諾 IME 自己剛刪除且能確認選取狀態的內容，不宣稱各 App 都能通用復原。

觸覺回饋先使用 `View.performHapticFeedback(VIRTUAL_KEY)`，提供開關並遵循系統設定，不用固定「震動幾毫秒」假裝不同手機的效果相同。不額外加入按鍵音效；按下文字鍵顯示放大預覽，不另設版型或預覽選單。[Android 官方觸覺回饋建議](https://developer.android.com/develop/ui/views/haptics/haptic-feedback)。

## 6. 實用功能優先順序

| 優先 | 功能 | 價值與邊界 |
| --- | --- | --- |
| P0 | 唯一排列、高度調整、可按的間隔、候選列、pressed／觸覺回饋 | 每個字都受影響；不提供舊布局或尺寸預設選單 |
| P1 | 長按常用中文標點與符號提示 | 參考圖的 26 鍵符號與 z「、」已完成，見第 12 節；`'`、`,`、`.` 的字碼角色保留，123／Emoji 入口維持 |
| P1 | 空白移游標＋文字編輯面板 | 左右游標、全選、複製、剪下、貼上；有 raw code 時先禁用會改外部選取的操作，並解釋原因 |
| P1 | 剪貼簿／常用片語 | 先做使用者開啟面板後讀取目前剪貼簿、手動釘選片語；歷史紀錄另行選擇啟用與保存期限，不擅自記錄輸入內容；私密欄位不顯示內容 |
| P1 | 數字／電話專用版面 | 依 `EditorInfo.inputType` 提供數字區，處理小數點、負號與電話符號；返回一般文字時恢復原布局 |
| P2 | 單手左右模式、底部上移 | 大手機更容易碰到兩側；縮窄也會降低字母寬，必須可一鍵返回全寬 |
| P2 | Emoji 最近使用／分類 | 改善現有初版面板；搜尋與完整 Unicode 分類另估資料成本 |
| P2 | 自訂片語／字碼捷徑、刪字手勢 | 片語以明確選取送出；字碼不套英文自動更正；刪字先處理預覽與邊界 |

不把英文自動更正直接套進嘸蝦米 raw code，避免改掉合法字根。滑行拼字、語音、雲端翻譯、GIF 搜尋與 AI 改寫各需要額外輸入模型或服務評估，先不與本次好按度改善綁成一包。

## 7. 可執行的實作任務

以下為分階段任務；任務 1–3 與任務 5 的字母長按符號已完成；任務 4 及其他進階功能留待後續。路徑均相對於 `app/src/main/`，新增檔案特別標示；不修改碼表、候選排序或輸入引擎。

### 任務 1：固定基準與設定範圍

- **檔案**：`java/me/osku/freeshiamy/settings/SettingsKeys.kt`、`settings/SettingsFragment.kt`、`res/xml/ime_preferences.xml`。
- **內容**：移除排版選單、QAZ 左移及新增尺寸預設；提供按鍵放大預覽並移除文字靠上；保留高度百分比、數字列、觸覺回饋、永遠顯示鍵盤、候選及隱私設定。舊版型偏好忽略，保留的設定值不覆寫。
- **完成證據**：新版設定畫面符合清單，升級後只有唯一排列。
- **依賴**：無。

### 任務 2：唯一幾何、視覺與回饋

- **檔案**：`java/me/osku/freeshiamy/FreeShiamyKeyboardView.kt`、`FreeShiamyKeyboard.kt`、`res/xml/qwerty_familiar*.xml`、`res/layout/input.xml`、鍵盤 vector／background 資源。
- **內容**：字母列 52dp、數字列 48dp、底列 56dp；高度百分比直接改 key geometry，文字不跟著拉伸。字母列滿寬、A 列半格錯列、第三列右側 Del；底列保留逗號及句點，單引號依追加需求收進 z 長按，空白加寬至 50%。淺灰無邊框、灰色空白條及綠色圓形 Enter。刪除舊 QWERTY XML／快取／切換分支。保留原生一般鍵 timer；空白觸控處理取消、關閉與雙拇指交接。
- **完成證據**：實際觸控 cell 與畫面一致；高度修改及旋轉不累積縮放；取消／隱藏後無延遲輸入；雙拇指兩種放開順序不重複或漏字；原有刪除邊界不變。
- **依賴**：任務 1。

### 任務 3：候選列與工具入口

- **檔案**：`java/me/osku/freeshiamy/ui/CandidateBarView.kt`、`res/layout/candidate_bar.xml`、`FreeShiamyIME.kt`。
- **內容**：固定 48dp 的候選／工具列共用位置，候選最小寬 48dp、raw code 區 64dp。閒置時顯示設定、切換鍵盤、收起；有內容時可開工具、返回候選，開工具不送出字碼。數字列開關只是唯一排列的延伸。
- **完成證據**：空／有候選時鍵盤不跳動；數字選字、原碼、反查與工具切換維持正確；文字靠上設定已移除；文字鍵按下會有放大預覽。
